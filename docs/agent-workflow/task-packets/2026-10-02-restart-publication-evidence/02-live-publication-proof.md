### Issuance, entry and terminal work

- `ImportMemoryPublicationService._issue_live_publication(rag_scope, attempt, new_rag_points, *, event_vector, event_profile) -> _LivePublication` performs complete read-only `_plan_intent`, `reserve_intent`, then issues one process-local opaque handle. Only this private factory may issue it; it is called directly by isolated integration fixtures. Its independent immutable **base issuance record** binds `self`, `self.documents`, `self.documents.documents`, `self.pair`, `self.pair.imports`, both vector services and authorities, the original live `ImportAttempt`, frozen task/source/scope/base/snapshot/event/old and new witness values, the frozen three-field `AttemptKey(user_id, task_id, task_lease_version)`, intent hash and both candidate IDs. After S3 put and same-repository verification, `_bind_verified_document(live: _LivePublication, verified: VerifiedDocumentRef) -> None` creates exactly one immutable **document continuation record** holding the original token and the document repository's independently copied issuance tuple. It rejects a second binding, foreign issuer or changed values. The base record cannot contain a token before S3 verification. A copied handle, copied scalar record, foreign instance, mutated handle or saved row cannot pass issuer identity checks.
- `ImportMemoryPublicationService._execute_live_publication(live: _LivePublication) -> DetachedImportMemoryPublication` accepts only its issuer's live handle and committed reservation; all other values refuse before I/O. `publish(...)` and normal runtime composition do not call this core. There is no constructor option or flag to enable it.
- Only after both sealed slots exist, the issuer creates `_FixedTerminalWork` with an independent record of exact callback object identity, C service identity, document continuation, frozen values and original attempt. `PostgresImportLeaseRepository.try_begin_committing(attempt, *, live: object | None = None) -> bool` and `complete(attempt, publish=None, *, terminal_work: object | None = None) -> ImportTaskRecord` preserve the old no-gate call signatures while receiving only issuer-validated private objects. For `live=None`, unresolved gate refuses before progress change or callback; no-gate legacy callback works as before. The durable branch requires issuer-record identity, same repository/database and exact saved seals. `complete` accepts exactly one of ordinary `publish` or issued `terminal_work`; no arbitrary callback may be supplied with durable work. A wrong callback/issuer, changed scope/value/attempt, stale handle or direct construction refuses before invocation.
- `complete` locks and checks the gate/evidence/rows under its own cursor, rechecks fresh task/user authority after blocking locks, then creates a one-transaction `_TerminalAdmission` and passes it explicitly to the fixed callback as `terminal_work.run(cursor, admission)`. Admission binds cursor/connection and active transaction, issuer record, current exact phase/version/hash, original attempt, and exact frozen operations. It is invalid after callback/transaction exit, cannot be reused in another cursor or nested call to widen scope, and grants no delete/failure/cleanup permission. Keep `_live` pure; gate validation never recursively calls `_live`.

### Document, evidence and phase contract

- `PostgresImportPublicationEvidenceRepository._read_exact_in_cursor(cursor, key: AttemptKey) -> FrozenEvidence | None` performs SELECT, bounded decode and full typed slot validation before returning, entirely inside caller transaction. `read_exact` may delegate to it.
- `append_document_in_transaction(cursor, live, verified, *, expected_phase, expected_version) -> FrozenEvidence`, `append_sealed_in_transaction(cursor, live, kind, sealed, *, expected_phase, expected_version) -> FrozenEvidence`, and `append_terminal_in_transaction(cursor, live, rag_receipt, episode_receipt, *, expected_phase, expected_version) -> FrozenEvidence` all require the original issuer's handle, exact key, current phase/version and null-to-value slot CAS. They return the next phase/version. They reject a second append even when bytes match; a different value is a definitive conflict. An ambiguous response is investigated by exact read-only proof and never retried as another write or external operation.
- The document append requires the original `PostgresDocumentObjectRepository` instance's issued `VerifiedDocumentRef`. Copy and compare its independent issuance tuple; no scalar token factory. The document wire slot contains exactly `user_id, document_id, bucket, key, version_id, sha256, size_bytes, record_hash, final_expected_hash`. `record_hash = sha256(canonical(record))`. With `unsigned_document_result` being those first eight fields, `final_expected_hash = sha256(b'1:' + intent_hash.encode('ascii') + b':' + canonical(unsigned_document_result)).hexdigest()`. `canonical` is UTF-8 JSON with sorted keys, compact separators, `ensure_ascii=False`, `allow_nan=False`; the schema prefix and both colon separators are literal bytes.
- Initial `intent` is version 1. Document append makes `document_verified` and increments version (normally v2). RAG sealed append keeps `document_verified` and increments version; episode sealed append makes `pair_sealed` and increments version; terminal append makes `terminal_committed` and increments version. Observation writes may advance version, so every append uses the just-read expected version and never hardcodes v3/v4/v5. No new phase or migration is invented.
- Each sealed slot is the exact current `_14` wire map: `generation_id, vector_kind, user_id, task_id, task_lease_token, task_lease_version, worker_id, user_lease_token, user_lease_version, namespace, index_key, base_revision, index_revision, snapshot_version, expected_count, content_digest, final_expected_hash`. Reconstruct the current nine-value `_owner_key` as `('import', user_id, worker_id, UUID(user_lease_token), user_lease_version, task_id, worker_id, UUID(task_lease_token), task_lease_version)` and compare it with the returned seal's `owner_key`; the wire strings are parsed to UUID values before comparison and there is no extra persisted owner tuple. The slot is derived only from returned verified `_SealedGeneration` and exact frozen intent. Terminal slot holds `final_expected_hash`, `rag_receipt`, `episode_receipt`, each the ordered 20 fields `RECEIPT_FIELDS` including actual immutable `created_at`, `sealed_at`, `published_at` selected in the terminal cursor. Never synthesize timestamps or accept a planned digest as seal proof.

### Detached proof and return behavior

- Create immutable `DetachedPairPublication(rag, episode, import_task)`, `PublicationProofEnvelope(attempt_key, intent_hash, final_expected_hash, phase, phase_version, rag_receipt, episode_receipt)`, and `DetachedImportMemoryPublication(pair, event_id, history_version, memory_version, document_ref, witness, proof)`. Legacy `ImportMemoryPublication` / `PairPublication` and in-process `reconcile(unknown)` remain intact.
- `app/import_publication_proof.py` exposes `ImportPublicationProofService(database).prove_exact(user_id: str, task_id: str, task_lease_version: int) -> DetachedImportMemoryPublication | None`. The service owns the database and evidence repository; callers supply only the frozen three-field key. It opens one `REPEATABLE READ READ ONLY` transaction, calls `_read_exact_in_cursor` there, and performs every pair/domain/receipt/task/audit/fence SELECT in that same cursor. Pure B pair selectors accept validated scalar scope/receipt descriptors; C domain validators accept frozen scalar intent/slots. Neither constructs `_PairContext` or `_Expected`.
- Return detached result only on fully validated `terminal_committed` (or later valid `proved_succeeded`) evidence plus succeeded task/audit. Return `None` for absent, mismatched, incomplete or tampered proof. Raise `PublicationProofUnknown(attempt_key, phase)` for a DB read/decoding failure that prevents a reliable verdict. The live core raises `DurablePublicationUnknown(attempt_key, phase)` for uncertain put/stage/upload/seal/commit responses and does not attach `_Expected`, `_PairContext` or a token. Definite prewrite refusal raises `ImportMemoryPublicationError`; live authority loss raises the existing lease/authority error before further I/O. Read-only proof with a fresh service may diagnose and return the detached result; a `None` or Unknown verdict never permits another S3/Qdrant stage, upload, seal or terminal attempt.
- Proof compares saved old receipts even if later `retired`; both saved new receipts by immutable UUID and all 20 fields including timestamps; exact saved History/Memory snapshot when current version equals saved version; at later versions, strict retained record/item/row/witness and tenant checks without demanding whole later snapshots equal the original. Check document reference/record hash, event metadata, task/source and audit identity/succeeded status, deletion/clear fences and exact witness. Empty generations use receipt IDs rather than nullable current head IDs. Missing head or zero vectors is never rollback proof. Optional S3 bytes are diagnostic only and cannot issue a token.
