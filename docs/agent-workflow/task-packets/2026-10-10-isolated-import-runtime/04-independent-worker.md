## Produced interfaces

### Providers

`open_isolated_providers(settings: IsolatedImportSettings, *, env=None, rag_transport=None, episode_transport=None)->IsolatedImportProviders` builds two actual engines before any claim. Read only explicit `ISOLATED_IMPORT_RAG_EMBEDDING_<suffix>` and `ISOLATED_IMPORT_EPISODE_EMBEDDING_<suffix>` values, mapped to existing RAG_EMBEDDING keys for each factory. Suffix set: PROVIDER, BASE_URL, MODEL, REVISION, DIMENSION, API_KEY, TIMEOUT_SECONDS, MAX_RETRIES, BATCH_SIZE. Each PROVIDER is mandatory; other values use existing validated defaults for that explicitly selected engine. No ordinary-provider environment inference. Both runtime profiles must exactly equal the two configured isolated profiles, including chunking/transforms/distance; mismatch refuses before network or claims. Distinct engines may share an identical profile; never silently adapt a configured profile. Errors are code-only, secrets and transport hidden in repr.

Properties `rag_runtime`, `episode_runtime`; `probe()->ProviderReadiness` freshly embeds one fixed non-user text using each engine and validates finite normalized output/dimensions before available=True. Configuration matching alone is not availability. Each probe uses a bounded retained operation, timeout at `provider_timeout_seconds`, at most one outstanding probe thread; busy/closed/timed-out probe returns unavailable. A late probe remains tracked and prevents spawning more probes until finished. Runtime construction does not invoke probe. Remote request timeout must not exceed min(existing 20-second limit, configured provider timeout); effective retries must not exceed min(configured retries, settings.provider_max_retries, 2). Actual outer deadlines also cover semaphore waits/retries, without changing the existing client.

`close(*,timeout_seconds:float)->bool` marks closed first, starts no more calls, waits at most the supplied bound for retained probe work, returns false if it remains alive. Do not claim to kill a thread. No process-global unbounded executor or thread-per-retry leak. Test transports are explicit test seams; CLI supplies none. Task05 will own providers and runtime together and use this exact probe for API admission.

Read-only `active_threads:tuple[Thread,...]` exposes a locked snapshot of retained live probe threads for Worker admission and lifecycle accounting. The Worker must recheck this snapshot immediately before ordinary claim, including after a later tenant's probe times out. Join/account each unique thread identity once; do not double count a probe also observed by preflight. Never use this interface to terminate a thread.

### Worker

`IsolatedImportWorker(runtime:IsolatedImportRuntime, providers:IsolatedImportProviders|None, *,worker_id:str)` requires worker-role trusted runtime, exact settings/profile identity when providers exist and one shared PG database across all composed repositories. It owns ordinary leases, recovery repo and lazy per-user immutable publication composition using runtime lazy clients, exact RAG namespace `pdf_<user_id>` and episode namespace `episodes`. No client creation/claim/provider probe in its constructor. Do not reuse a mutable trusted episode scope across users. providers=None is explicit recovery_only mode: run_one_ordinary returns false without ordinary_ready, claim, provider, source/storage, issue or adapter calls. It is never an embedding fallback.

`run_one_ordinary()->bool` returns false if no eligible claim; true if one attempt was claimed and supervised, including refused/held outcomes. It does not claim while a previous attempt or provider operation is still alive. `run_one_recovery()->RecoveryOutcome|None` performs bounded filtered expiry/queue work. `run_forever(stop_event)->WorkerExit` alternates recovery and ordinary, waits interruptibly when idle, stops admitting new work on stop. `WorkerExit` has `clean:bool`, `reason:str` (stable codes only), `ordinary_attempts:int`, `recovery_attempts:int`, `active_threads:int`. `close()->WorkerExit` is idempotent, stops renewals and waits at most configured settings.stop_wait_seconds; nonzero active threads requires clean=false. Runtime/provider resource closing must wait until borrowed work ends or explicitly report resources not safely closed; do not close resources then call the exit clean.

CLI `main()->int`: validate worker settings first, then construct providers. Produce `IsolatedProviderConfigurationError` in the new provider file, carrying a stable code only, for explicit provider-construction refusal (missing prefixed PROVIDER/key, unsupported executable engine, invalid embedding parameters or exact-profile mismatch). Convert existing EmbeddingFailure('configuration') only at this construction boundary. Catch only this typed error in CLI and continue with providers=None and `open_isolated_runtime(settings,provider_probe=None)`; report the stable recovery_only mode and refusal code. Otherwise open runtime with providers.probe, then compose Worker. Invalid isolated settings/profile JSON, role, DB/schema identity remain fatal exit 2; do not downgrade arbitrary exceptions or runtime/DB failures. On failed runtime opening close any constructed bundle. Later probe failure leaves ordinary unavailable without rebuilding providers. SIGINT/SIGTERM set stop event. Exit 0 only for clean stop (including explicitly reported recovery_only mode); 2 fatal configuration/composition refusal; 3 timed-out shutdown/late work. No full local app import, register, schema initializer, worker embedding fallback or credential output.

## Selection and forward path invariants

Form a validated frozenset of ready IDs, always a subset of trusted IDs; empty selects nothing. Ordinary claim uses this subset in SQL before candidate selection. This deliberately amends the plan's earlier exact-full-allowlist shorthand: recovery and expiry use the full trusted set, ordinary may safely narrow it. A provider/baseline failure for A must not mutate A's tasks or prevent ready B/recovery. Recheck the claimed user's readiness before preparing or issuing; readiness is not a durable write grant, existing task/user authority remains final.
2. One non-daemon retained attempt thread owns all forward steps and the original attempt/service/live handle. A supervisor observes monotonic overall attempt deadline, stop and heartbeat loss. Start heartbeat after claim, renewing both authorities on original attempt; returned snapshots never replace the attempt/live. Heartbeat sleeps interruptibly and is separately retained, never infinite retries.
3. Verify original pinned source through artifact service, then real `prepare_import_document`; embed episode text exactly `用户导入了文档：{attempt.task.original_name}` with episode engine. Validate exact profile and finite dimension. It locks in existing user-first order and checks both authorities with fresh post-lock DB time; user-lease-only coordinator checking is insufficient. Immediately end this transaction before external work, then recheck stop/loss/deadline before starting the stage. Run potentially blocking checks on the retained attempt thread without a Worker mutex, never the supervisor. This private coupling and the exact episode literal must be pinned in focused tests; no new authority protocol. Once issue begins, original issuance/adapter/proof handle authority; no ordinary check that misclassifies committed success as failure.
4. Overall attempt_seconds defaults 300; provider preparation/probe/event operations are externally supervised at provider_timeout_seconds default 30, bounded also by remaining attempt time. No repeated provider retry thread after timeout. A timed-out operation remains visible; stop renewal, do not issue/execute new steps from its late result, and do not admit another ordinary attempt until retained work is finished. CPU parsing and external source/adapter work also count in the overall budget. Existing remote client batch budget does not replace outer supervision.
5. The attempt thread calls `_issue_live_publication` at most once, then `ImportPublicationWorkerAdapter(publication,recovery,enabled=True).run_once(live)` at most once on that original object. Never use legacy publish/complete/mark_succeeded. Before issue starts, deterministic parse/embedding input/configuration refusal may use `leases.fail` only while original authority is still live; unknown dependency outcomes may simply stop renewal and let expiry recovery decide. Once issuance starts, any exception is conservatively held; never ordinary fail/cancel/release/retry an ambiguously issued attempt.
6. Stop/loss/deadline prevents starting further stages and renewals; an already executing irreversible adapter stage cannot be physically cancelled. Report it as active/uncertain until completion; its existing fresh-clock/fencing checks and authoritative recovery decide its effects. Do not claim that an in-flight heartbeat or terminal call was undone. At most one already-started heartbeat may finish after a stop signal; no subsequent heartbeat starts. A late attempt must not initiate a new issuance/adapter invocation.
7. Heartbeat loss racing completed publication is resolved by exact existing proof, not another terminal write. If an originally issued adapter result and fresh exact proof establish committed success, retain that truth; otherwise held/uncertain and stop renewal. No polling infinite proof retries. Never rewrite an already committed successful attempt as failure due to a later heartbeat observation.

## Separate recovery and shutdown

Recovery requires trusted schema readiness only, independent of providers/ordinary baseline and vector writes. Use full trusted IDs for `leases.recover_expired(limit=100,allowed_user_ids=trusted)`, then recovery `claim_next(worker_id,lease_seconds=lease_seconds,allowed_user_ids=trusted)` and `prove_or_hold` on the current exact claim. Unlike ordinary heartbeat, recovery.renew changes both captured expiry timestamps: if used, invoke it serially before proof, adopt its returned RecoveryClaim and pass that exact snapshot to prove_or_hold. No concurrent renewal during proof or another renewal, no background recovery heartbeat, no manually refreshed claim fields. ### Complete retained-operation supervision

The stop/reporting supervisor executes no blocking runtime/database/storage/close calls. Use bounded waits on the following retained non-daemon lanes, with no executor pool and at most one outstanding operation per lane:

- Preflight lane: one round of per-user ordinary_ready, ready-subset construction and ordinary claim, with a total monotonic observation budget of settings.provider_timeout_seconds. This is an orchestration budget for all I/O, not merely embedding timeout. Before claim recheck stop/deadline and providers.active_threads. On a late readiness result do not claim; on a late claim do not start forward work or heartbeat, let persisted leases expire. Clear the lane only after actual completion. A timed-out preflight permits the separate recovery lane to run, but no replacement preflight/ordinary attempt while the old operation or probe remains alive. A claim acquired within budget transfers the original handle to the single attempt lane only after preflight completes and stop/deadline is rechecked. Selected-user readiness is supervised within the attempt's provider-stage and remaining overall budget.
- Recovery lane: recovery_ready, expiry scanner, recovery claim, optional serial renewal, proof, each preceded by stop/deadline checks, share one total settings.provider_timeout_seconds observation budget per round. Do not call any of these synchronously on the reporting supervisor. A late expiry/claim must not initiate another stage; retain already-started database work without claiming its mutation was cancelled. A late proof may finish under its exact captured authority or fail closed. No second recovery round until this lane drains. Recovery stays eligible when ordinary preflight/probe is late; distinct persisted authorities and existing fences arbitrate any overlap.
- Attempt and heartbeat lanes: one original forward attempt and one separately retained heartbeat as specified above. Authority checks, source/preparation/issuance/adapter calls all run on the attempt lane; a blocked heartbeat remains accounted and admits no replacement heartbeat. No Worker mutex is held over database/external calls or joins.
- Close lane: on first stop/close request start one retained cleanup observer; it waits for all borrowers, including preflight/recovery/probe/heartbeat, to actually drain before running provider close and runtime.close. It uses the same absolute monotonic stop deadline as all other joins; never restart a close lane or call a second unbounded close from context-manager/finally/CLI. If a borrower survives the deadline, leave resources owned and unclosed and report unclean. The retained operation's completion/finalization owns eventual cleanup after borrowers drain; repeated close observes the same operation, never begins duplicate closure. A slow closer is itself retained and counted as active.

Stop begins one absolute deadline now+settings.stop_wait_seconds; remaining joins/close observation share it, never receive individual fresh ten-second budgets. Define clean at the observable boundary only: all retained work drained, no late live operation, provider close returned true (or explicit providers=None), and runtime.close returned. Existing runtime.close swallows underlying closer exceptions, so report only completed runtime close attempt, never independently verified release of every PG/S3/Q resource. No stronger resource acknowledgement is introduced here.

Each retained background operation has bounded observation/join and recorded ownership. On stop, signal and stop starting ordinary/recovery calls, join within settings.stop_wait_seconds total, report any active thread/resources. No daemon thread or invisible fire-and-forget publication. A false clean CLI exit is a failure. Bounded WorkerExit reporting and a nonzero main() return do not guarantee actual OS process termination: a live non-daemon thread keeps Python alive. This four-file in-process design promises bounded reporting, not a ten-second process-exit SLA or hard cancellation. Tests release deliberately delayed work in finally so the test process does not leak threads. Real separate-PID restart/crash acceptance stays Task06.
