## 1. 已确认目标与方案

本阶段将 `/search` 占位页替换为“检索当前用户已经导入的文档”。支持显式多文档范围、语义检索、片段与页码、复制引用、进入问答及保存可追溯笔记。联网查找论文是后续独立阶段。

已比较的方向：

1. **独立检索服务与结构化结果（采用）**：复用现有 RAG，建立稳定接口与来源边界，前端不依赖旧版字符串格式；为后续外部来源扩展保留空间。
2. 直接搬迁 Gradio 文本框：交付较快，但引用、交互与错误判断依赖展示文本，不能作为长期产品接口。
3. 同时接入联网学术搜索：增加外部服务、许可、限流和导入安全边界，不纳入本切片。

## 2. 仓库事实与需补齐的边界

- `assistants/pdf_learning_assistant.py:search` 已支持显式文档集合；旧 UI 用 `ui/gradio_app.py:search_pdf` 调用并展示字符串。
- `hello_agents/tools/builtin/rag_tool.py` 当前生效的 `_search` 只拼接展示文本；不能通过解析这些文本构造新版结果。该文件存在同名方法定义，实施时必须定位真正生效的方法并以兼容测试约束相关改动，不顺带重构整个工具。
- `RAGTool.execute_result` 与 `app/qa_answer_engine.py` 已建立结构化工具结果和应用适配器模式，可沿用此方向。
- `DocumentLibraryService` 提供会话用户下的文档列表与删除围栏过滤。
- 笔记目前只支持问答消息/问答引用来源；`app/database.py` 的 `note_sources.source_kind` 有 CHECK 约束。因此直接从检索保存笔记需要正式扩展来源模型，不能伪造问答消息或只复制正文冒充可追溯来源。
- `app/rag_authority.py`、`app/rag_inventory.py` 是停止写入后的离线迁移工具，不得用于在线检索、在线来源解析或每次请求的全库扫描。

## 3. 用户流程与产品规则

1. 从当前用户文档库明确选择 1–10 篇文档，输入 1–1000 字符的非空查询，再点击搜索；未选择时不默认扫描全部文档。
2. 默认语义检索，复用部署当前激活的嵌入模型与索引身份；本阶段不新增模型、不调用生成式 LLM 组织检索结果。
3. 默认返回前 10 条，允许 5、10、20 条。显示“返回 N 条相关片段”，不得冒充全库命中总数，不提供虚假的总页数。
4. 每条显示文档名、真实片段、PDF 页码或“未提供页码”、检索排序及可复制的来源说明。分数如展示，标为“检索分数”，不得显示为正确率/置信百分比。
5. 片段中的字面命中可用安全文本高亮；语义命中不一定包含查询原词，不伪造高亮。
6. “基于此文档提问”只携带该结果的文档 ID 进入现有 QA 文档范围确认流程，不自动生成回答或创建隐藏问答记录。
7. “保存为笔记”打开可编辑草稿，并由服务器解析真实来源；用户点击保存后才写入笔记。保存成功可打开该笔记。
8. 复制引用只使用已有文档名、页码/片段标识；不编造作者、DOI、出版年份或正式参考文献格式。

## 4. 架构与接口方向

调用方向为 React → FastAPI → DocumentSearchService → RAG 检索适配器 → 当前后端。应用服务负责身份、文档授权、范围和返回前校验；RAG 负责召回；笔记服务继续拥有笔记持久化和投影。

新增检索请求使用 `POST /api/v1/search`：查询正文不进入 URL、浏览器历史或普通访问日志；要求会话与 CSRF，禁止缓存响应。请求仅包含 `query`、`document_ids`、`limit`，不接收 user_id、collection、namespace、模型或服务器路径。

结构化响应包含请求标识、实际文档范围、结果列表和结果数量。每条结果包含：

- 文档 ID 与展示名；
- chunk 标识、内容摘要校验值、页码/章节定位（真实缺失时为空）；
- 经过长度上限约束的片段、排序和检索分数；
- 来源类别 `document_chunk` 与可供服务器重新解析的引用字段。

来源身份绑定文档及片段内容，不把向量 collection 名或模型版本当作永久引用主键。显示时可以另带诊断用检索策略信息，但不泄露内部索引路径。模型重建不应让已经保存的笔记正文或来源快照消失。

检索适配器补充 `execute_result("search")` 的结构化数据，同时保留旧版字符串输出。只改动与本切片相关的工具边界，保护现有 QA 和迁移行为。

## 5. 笔记来源演进

为笔记正式增加 `document_chunk` 来源，与现有 `qa_message`、`qa_citation` 并存。新增来源包含文档 ID、chunk 标识、内容校验值、定位和服务器生成的标题/片段快照；不需要 qa_message_id。

客户端提交来源标识，不提交可被当作权威来源的标题、页码或摘录。由独立文档片段解析接口在当前用户和指定文档内读取、核对内容校验值，再交给 NoteService；不得直接依赖检索页面缓存或客户端传入正文来证明来源。

解析必须使用在线后端的按标识读取/有界查询能力；不调用离线迁移 inventory。JSON 与 Qdrant 实现共享同一解析契约。笔记正文由用户编辑，来源快照表示服务器解析时的真实内容，不承诺跨系统的全局事务快照。

保存继续沿用现有幂等请求 ID、乐观版本、SQLite/outbox 和投影机制；最后写入时必须检查文档删除围栏。来源已不存在或校验值发生变化时要求重新检索，不静默绑定到另一段内容。

文档删除后保留用户编写的笔记正文，按照既有删除规则清理关联来源快照并标记来源失效；禁止通过旧结果重新保存已删除来源。

由于现有表限制来源枚举，不重建或放宽 `note_sources`：新增向后兼容的
`note_document_sources` 附表，来源类别由表类型确定，并通过既有笔记复合外键、
用户/文档索引和删除标记维持相同隔离语义。新版读取时将两类表投影到统一
`NoteSource`。已验证旧表 DDL/行数据不变、全新库、重复初始化及部分索引重建；这只
保证旧表可读取，不代表旧镜像能够继续正确清理新附表的来源。实际回滚必须通过安全
更新器配对恢复旧镜像和一致性冷备份，不允许仅切旧镜像后继续使用含新来源的数据库。
初始化失败时应用不继续启动；不把多语句初始化脚本表述为已证明整体原子回滚。

## 6. 隔离、并发与错误

- 先验证全部文档归属和可用性再检索；混入其他用户文档时整个请求拒绝，不能部分执行并泄露哪个 ID 存在。
- 检索结束后重新验证文档范围及删除围栏；期间发生删除时拒绝发布旧结果，不把失败包装成“没有找到”。
- 网络嵌入请求不持有用户写入锁。限制单用户与进程级并发，复用有界超时；满载返回可重试状态，禁止无界线程/后台请求。
- 输入无效、无结果、来源失效、删除冲突、服务超时/不可用分别有明确状态。错误不包含文档正文、API Key、文件路径或上游堆栈。
- 前端查询按用户和完整请求隔离；新请求发出后旧响应不能覆盖新结果。退出登录立即卸载私有内容；取消浏览器请求不宣称能够取消已发往模型服务的计算。
- 修改查询/文档范围后清除旧结果操作入口，明确提示重新搜索。失败时保留输入，允许用户重试。
- 不新增持久化搜索历史，不在 localStorage 保存查询、片段或草稿来源。会话恢复后重新检索。

## 7. 三档 UI 与设计交接

沿用“知研／智能文档学习助手”、现有 Penpot tokens、导航外壳与组件。页面标题“文献检索”，说明“在已导入文档中查找相关片段”。采用范围选择、查询区、结果列表和片段详情的内容层次；具体画板在规格确认后设计并审阅，不把本文当作 Penpot 源文件已更新的证据。

- 桌面：1440×1024 验收，空间足够时结果与详情双列。
- 平板：1024×768 验收，窄列时详情转抽屉，范围控件保持可操作。
- 手机：390×844 验收，单列结果、详情面板，操作目标至少 44px。
- 覆盖未选择、待搜索、加载、成功、空结果、错误、来源失效和笔记保存状态。
- 键盘可到达全部操作，详情面板有焦点管理，搜索状态通过 live region 播报；文本采用现有可访问颜色，不仅依靠颜色表达状态。

## 8. 验收与发布门槛

1. 后端：显式范围、1/10/超限文档、查询长度、结果上限、跨用户拒绝、删除竞争、排序/来源、空/错区分、no-store、认证和 CSRF。
2. 适配器：JSON/Qdrant 结构化契约一致；旧版文本和 QA 行为不变；无网络测试使用隔离夹具。
3. 笔记：旧库迁移、幂等、来源篡改/过期、文档删除清理、并发围栏与 QA 来源兼容。
4. 前端：用户切换、请求乱序、查询变更、空/错/加载、复制成功/失败、QA 入口、笔记草稿和保存交互。
5. 三档 E2E：导入测试文档 → 搜索 → 查看片段/复制引用 → 发起问答 → 保存并打开笔记 → 删除文档后验证失效来源；无水平溢出及严重/关键 axe 违规。
6. 发布：相关回归与全量回归、构建、npm 审计、冷备份、镜像安全门槛、真实 BGE-M3 检索和 LLM 深度烟测；用临时测试文档，不打印用户内容与密钥。
7. 最终集成评审通过后才能声称阶段完成；生产运行仍只包含 App 和 Qdrant，稳定目录保持 `D:\python_self_agent`。
