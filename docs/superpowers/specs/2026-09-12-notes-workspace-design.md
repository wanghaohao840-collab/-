# 学习笔记工作台设计（已确认）

## 范围

以用户本条“学习笔记”请求为准；附件中的“文献检索”要求仅作为产品背景，不扩展为第二个页面重构。保持 FastAPI 路由、字段、响应和用户隔离不变。沿用当前 React 查询、API 层和版本冲突机制。

## 方案选择

推荐三栏阅读工作台：左侧集中检索和笔记库，中间突出写作，右侧解释来源和上下文。它最符合现有数据模型及本次要求。

仅调整现有表单样式成本较低，但不能解决信息层级；引入块编辑器能增强写作，但会扩大依赖、正文序列化和兼容范围。本次均不采用。

## 页面结构

- Header：轻量 eyebrow“从理解到沉淀”、标题和指定副标题；紧凑“新建笔记”“清空筛选”；清空全部笔记放入更多操作，保留现有确认流程。
- 笔记库：搜索“搜索标题、概念、正文”，标签和来源筛选，下方展示当前列表数量及加载更多。接口没有总数时不将已加载数量冒充全库总数。区分全库为空与筛选无结果。
- 列表项：标题、一句正文摘要、标签、实际来源类别及数量、最近更新时间。浅绿选中态，键盘可操作。
- 工作区：可编辑标题、真实保存状态和时间、保存及更多操作；轻量概念和标签行、编辑/预览 tabs、宽松正文排版和指定 placeholder。保留手动保存，不引入自动保存。
- 来源与上下文：显示真实 citation ID、文档名称、存在时的页码、证据摘要；删除来源保留删除提示。来源跳转只使用已有可验证的路由和定位能力，不虚构原文页跳转。
- 长期积累：实际 QA 来源计数、当前概念、更新时间，以及真实的记忆投影状态。没有关联概念推荐或 Memory Hint 数据时显示简短空状态。

## 接口兼容与能力边界

现有 Note 无独立 title 字段。标题编辑映射到 Markdown 首个一级标题；没有一级标题时可在显式标题编辑后插入，绝不在加载旧笔记时自动改写正文。标题和正文保持同步，概念仍保存至 concept。

已有来源只在创建笔记时由服务端解析，更新接口不能增删来源。“从 QA 导入”“从文献检索添加”导航到现有流程并说明将创建来源笔记，不声称为当前笔记追加来源。手动引用和移除来源不提供可执行操作，保留组件能力接口供未来扩展。

AI 整理、关键词、复习卡片仅保留组件扩展位置；无 API 时不渲染可点击操作。不会猜测相关概念、掌握度或知识联系。

保留 note id、source、citation、document_id、locator/page 和删除状态。保留未保存离开保护、乐观版本锁、失败草稿、复制草稿和投影重试。

## 视觉与响应式

暖灰白背景接近 #F7F9F7、白色 surface、深灰绿文字，森林绿仅用于 CTA/状态。浅边框、10–14px 圆角和极轻阴影。页面标题 32px，区块标题 18px，正文 14–15px，meta 12–13px。

宽屏三栏，笔记库约 260px、来源约 280px，中间弹性。平板来源转抽屉；手机在列表与编辑之间切换，筛选和来源使用抽屉，保存入口保持可达。保留焦点恢复、Escape 关闭及 tab 圈定。

## 组件与数据

复用 features/notes 中的类型、API 和 hooks，不新建重复 API 层。页面负责查询与路由，workspace 负责草稿和交互。拆分 Header、Filters、Library/ListItem、WorkspaceHeader、Metadata、EditorTabs、Editor/Preview、Sources/SourceCard、EmptyState；按职责拆分，不为满足名称清单制造空壳组件。

## 验证与交付

覆盖标题正文同步、旧笔记不被隐式修改、清空筛选与清空笔记区分、真实来源元信息、保存失败/版本冲突、空态及移动端抽屉。运行相关单元测试、typecheck/lint/build，以及桌面/平板/手机视觉和无障碍检查。验收使用隔离数据；本轮代码重构完成后先提供预览和验证记录，不自动操作生产数据库。
