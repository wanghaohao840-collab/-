# 简历能力化表达与版式优化设计

## 1. 目标

以当前的 `冯嘉文_简历_大模型应用开发工程师_面试优化版.pdf` 为内容基线，参考以下公开材料生成新的 PDF 副本：

- B 站文章：<https://www.bilibili.com/opus/1232699006039097347>
- 老鱼简历模板：<https://laoyujianli.com/share/aiyupi>

本轮重点不是增加更多技术名词，而是让招聘方在短时间内看懂候选人掌握了什么、能完成什么工作、有哪些项目证据。不得覆盖原始简历或现有面试优化版。

## 2. 已确认的核心方案

专业技能采用“能力分组式”写法。每组同时包含：

1. 掌握程度；
2. 关键技术；
3. 能独立完成的工作；
4. 可由现有项目或仓库验证的能力边界。

不使用“精通”等难以证明的表述；不加入当前项目没有证据的 MCP Server、Agent Skills、Prometheus、Grafana、商业化运营等内容。

## 3. 专业技能文案

### AI 应用开发

掌握 RAG、Agent、Memory、Function Calling 与 Prompt Engineering，能够独立完成文档导入、检索问答、工具调用、会话记忆和来源引用等大模型应用链路。

### 检索与知识工程

熟悉 Qdrant、Hybrid Retrieval、MMR、Neo4j 与 GraphRAG，能够实现按用户和文档隔离的向量检索、跨文档知识关联、结果过滤及稳定引用。

### Python 后端开发

熟悉 Python、FastAPI、SQLAlchemy、MySQL、SQLite 与 Redis，能够完成异步 API、认证鉴权、缓存、事务处理及数据一致性保护。

### 工程化与 AI 编程

熟悉 Docker Compose、pytest、Git 及 Linux / Windows 单节点部署运维；能够使用 Codex、Claude Code 与规范驱动流程完成需求拆解、实现审查、自动化验证、备份恢复和升级回滚。

## 4. 其他内容调整

### 顶部定位

- 求职意向从“RAG / Agent 工程化方向”调整为更有证据感的“具备 RAG / Agent 工程化开发经验”。
- 保留姓名、电话、邮箱、所在地、毕业时间、GitHub 和照片。
- 不虚构作品集或线上项目地址；GitHub 仍使用当前可验证链接。

### 项目经历

- 保留“多用户智能文档学习与知识问答平台”为主项目。
- 将项目要点继续压缩为“技术决策 + 解决的问题 + 可验证结果”，减少纯功能清单。
- 保留已有真实数据：4 种文档格式、最多 10 篇联合问答、单批最多 20 个文件、最多 4 个用户并行、800+ 自动化测试，以及已验证的定向测试结果。
- 增加一条规范驱动的 AI 编程实践，明确人负责需求、架构、取舍和验证，AI 工具负责辅助提效；不声明未经测量的代码生成比例或效率提升百分比。
- 保留新闻资讯后端项目作为传统后端能力补充，但允许压缩重复的框架描述，为主项目和专业技能让出空间。

### 个人优势

- 删除或改写缺乏证据的“学习能力强”“重视工程质量”等泛化表述。
- 优势只保留可验证事实，例如独立交付闭环、自动化测试规模、部署恢复能力及 CET-6 英文资料阅读能力。

## 5. 版式设计

- 保留当前两页 A4、蓝色主视觉、顶部照片和可点击 GitHub 链接，不整体照搬参考模板。
- 吸收老鱼模板的信息层级：专业技能改为 4 组短段落，组名加粗，描述紧随其后。
- 第一页必须继续出现主项目标题和至少 3 条核心要点，避免技能描述把项目完全推到第二页。
- 重新分配主项目分页位置，减少第一页底部大面积留白，同时避免第二页拥挤。
- 保持文本可搜索、可复制，避免图像化文字；照片边框继续与照片本体对齐。

## 6. 验证标准

1. 新文件写入 `output/pdf/`，使用新的描述性文件名，不覆盖任何已有 PDF。
2. PDF 为 2 页 A4，所有中文正常显示，无裁切、重叠、黑块或异常留白。
3. 专业技能包含上述 4 个分组，并同时出现技术关键词和能力说明。
4. 不出现无法由项目、代码、测试或既有经历证明的新技能和量化结果。
5. 主项目仍是视觉和内容重点，第一页能够看到项目经历。
6. GitHub 链接可点击，正文可搜索，照片无右侧白边。
7. 用文本提取检查关键文案，再以 180 DPI 渲染全部页面进行逐页视觉检查。

## 7. 非目标

- 不新增虚构的实习、奖项、作品集、线上用户数据或性能提升比例。
- 不发布或推送项目代码，不修改远程仓库。
- 不重新设计当前软件项目的功能或架构。
