# 大模型应用开发工程师简历改写设计

## 目标

基于现有三页中文简历，生成一份独立的两页 PDF 副本，用于投递 2027 届“大模型应用开发工程师”岗位。原始 PDF 保持不变。

主求职意向统一为：

> 大模型应用开发工程师（RAG / Agent 工程化方向）

相邻岗位包括 AI Agent 应用开发工程师、Agent 应用全栈工程师、Python 后端开发工程师（AI 应用方向）和智能知识库平台开发工程师，但不在简历顶部并列堆叠。

## 内容依据

改写只采用以下能够核实的信息：

- 原简历中已有的个人信息、教育背景、英语水平和两个项目经历；
- 当前仓库代码、配置、提交记录和 README 能够证明的已实现能力；
- 当前测试收集结果以及本次定向测试结果；
- 目标岗位中实际出现的 RAG、Agent、Memory、Tool Calling、后端工程和部署能力要求。

不把规划项、尚未上线的作品、无法复现的性能提升、虚构访问量或未经验证的算法经验写成已完成成果。

## 版式

采用两页 A4、蓝白配色、单栏工程简历版式，保留原证件照。

第一页依次包含：

1. 姓名、求职意向和联系方式；
2. GitHub 项目地址；
3. 教育背景；
4. 三组精简专业技能；
5. 核心智能学习助手项目。

第二页依次包含：

1. 核心项目的工程化成果；
2. FastAPI 新闻资讯后端项目；
3. 有证据支撑的个人优势。

删除原第三页的大面积留白，不单独保留“校园与实践”“规划方向”和重复的“个人亮点”板块。

## 顶部信息设计

顶部必须让招聘方在首次扫读时看到：

- 明确的单一求职方向；
- 电话、邮箱、常居地、毕业时间；
- 可访问的 GitHub 仓库地址。

不添加尚不存在的个人作品集网站或线上产品地址。

## 专业技能设计

专业技能压缩为三组，并按目标岗位相关性排序：

1. AI 应用：RAG、Agent、Function Calling、Memory、Prompt Engineering、Qdrant、Neo4j / GraphRAG、OpenAI Compatible API；
2. 后端开发：Python、FastAPI、SQLAlchemy、MySQL、SQLite、Redis；
3. 工程实践：Gradio、Docker Compose、pytest、Git、Linux、Windows 单节点部署运维。

PyTorch、Transformers、AutoGen、LangGraph、CNN、RNN 等缺少当前项目直接证据或容易被算法岗深挖的关键词不作为核心技能展示。Transformer 原理可在面试准备材料中保留，不占简历核心空间。

## 核心项目设计

项目名称调整为“基于 Memory + RAG + Agent 的多用户智能文档学习助手”。开头使用一行说明产品定位和个人职责，不再保留长段项目背景。

项目内容控制在六至八条，每条尽量包含决策、技术方案和可核实结果：

- 分层架构与多用户数据隔离；
- PDF、TXT、MD、DOCX 导入，以及 `document_id` 和用户 namespace 双重范围控制；
- 最多十篇文档的联合问答、对比分析和联合总结；
- JSON / Qdrant 可切换 RAG、混合检索、页码级来源和稳定引用；
- Neo4j 文档图谱、GraphRAG 混合上下文和跨文档规范实体；
- 单批最多二十个文件、最多四个用户并行的持久化异步导入、阶段进度、失败重试和重启恢复；
- Docker Compose 与 Windows 单节点运维、备份、恢复演练和升级回滚；
- 覆盖单元、契约、集成和验收层的自动化测试体系。

测试数字采用“仓库可收集 800+ 项自动化测试用例”；只有完整套件在最终制作阶段成功运行时，才改写为精确的通过数量。本次已经通过的 GraphRAG、批量导入和部署相关 113 项定向测试可作为事实校验记录，但不和未运行的测试合并表述为全部通过。

## FastAPI 项目设计

第二个项目压缩为四条：

- Router / Schema / CRUD / Model / Cache 分层；
- FastAPI、SQLAlchemy AsyncSession 和 aiomysql 异步数据访问；
- UUID Token、密码哈希、过期控制和鉴权依赖；
- Redis Cache-Aside、MySQL 持久化、事务回滚和统一异常响应。

删除普通 CRUD 功能的逐项罗列，保留能够证明后端基础和工程能力的内容。

## 个人优势设计

个人优势最多三条，并且每条都带证据：

- 独立完成需求分析、架构设计、实现、测试和部署闭环；
- 建立多层自动化测试和故障恢复机制；
- CET-6，可直接阅读英文技术文档和开源项目源码。

不使用“学习能力强”“善于团队协作”“热爱编程”等没有证据的表述。

## 文件与隐私边界

- 不覆盖或修改原始 PDF；
- 最终文件写入仓库 `output/pdf/`；
- 输出文件名为 `冯嘉文_简历_大模型应用开发工程师版.pdf`；
- 中间渲染文件写入 `tmp/pdfs/`，交付前清理；
- 不把电话、邮箱、证件照或生成后的简历提交到 Git；
- 设计文档不记录电话、邮箱等个人敏感信息。

## 验收标准

内容验收：

- 求职方向唯一且与项目能力一致；
- 所有完成项均能由原简历或当前仓库验证；
- 不包含规划项、虚构指标或无证据技能；
- GitHub 链接可以点击或复制；
- 两个项目的技术边界清晰，没有重复堆砌。

视觉验收：

- 恰好两页 A4；
- 第一页能够看到核心项目；
- 无文字裁切、重叠、乱码、黑块或孤立标题；
- 字号、行距、缩进、项目符号和页边距一致；
- 第二页没有明显大面积空白；
- 证件照比例正确且清晰；
- PDF 文本可复制和检索。
