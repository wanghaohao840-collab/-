## 1. 目标与范围

将文档库、基于文档的问答所使用的 RAG 嵌入，从本地测试向量升级到
硅基流动免费 `BAAI/bge-m3`。同时建立模型身份校验、可恢复重建、验证后
切换及不丢失新数据的回滚机制。现有 LLM 配置、文档/用户隔离、来源引用、
Notes 数据和 Windows 运维任务不能被这次切换破坏。

本规格的产品范围是文档检索；不是把所有个人学习记忆一并发往云端。
Semantic/Episodic/Perceptual Memory 继续使用当前本地嵌入配置，不因
设置文档嵌入密钥而隐式切换。其后续升级须有独立的数据范围和索引迁移，
不得宣称本阶段已经完成所有 Memory 的生产级向量化。

后续已授权的资源上限、日志/磁盘/备份策略、默认本机绑定调整保持在路线中，
在本阶段验收后分别处理。此次不引入本地模型容器、GPU、重排序器、稀疏向量、
多节点部署或零停机双写；不将原有文档重新解析或修改切块规则与模型迁移混在一起。

## 2. 已核实的现状

- `hello_agents/memory/embedding.py` 提供全局 `SimpleEmbedding`，默认 384 维；
  它是测试哈希特征，不是语义模型。RAG 和三类 Memory 共用其入口。
- `hello_agents/memory/rag/pipeline.py` 和 `qdrant_pipeline.py` 均读取
  `get_dimension(384)`，目前没有外部嵌入配置。
- JSON RAG 的 `_to_vector` 和缓存加载会补零/截断维度；加载错误会警告后继续。
  对真实模型不能保留这种不兼容数据被悄悄接受的行为。
- Qdrant 存储已经检查维度和距离，但仅维度相等不能证明模型兼容。
- `create_rag_pipeline` 已让 `QDRANT_COLLECTION` 优先于调用方默认名称，
  不必因为 `app/runtime.py` 中有默认字符串而重写集合选择逻辑。
- Qdrant payload 保留 chunk 内容、命名空间、document ID、chunk index、
  文档版本和来源字段，可在不重新解析原文的情况下重建向量。
- 根目录 `compose.yaml` 已通过 `env_file` 读取 `deploy/.env`。
  Qdrant 使用外部 Linux volume；Windows 运维有共享 `operations.lock`。
- 稳定 `.env` 含已配置 LLM 密钥，受 Git 忽略。不得打印、复制到规格或提交。

## 3. 方案比较与选择

1. 免费 BGE-M3 API：无模型服务维护成本，适合当前内存有限的开发机；
   需要云端传输和限流处理。采用此方案，实际效果用项目评测确认。
2. 本地 Qwen3-Embedding-0.6B：无 API 费用，数据不离机；需要额外推理资源、
   模型版本维护及性能验证。保留为未来独立适配器，不在此次安装。
3. 付费嵌入 API：可作为后续质量/容量对照；不自动选择收费模型作为故障回退。

免费是当前平台政策，不承诺永久免费、无限流或生产 SLA。启动和探测必须显示
实际模型名称；本部署预设必须精确为 `BAAI/bge-m3`，不带 `Pro/`。

## 4. 配置及密钥交接

实施后在 `deploy/.env.example` 与运行中的 `deploy/.env` 增加独立配置段。
下表是待实现的配置契约，不是目前已经生效的变量。

| 变量 | BGE-M3 部署值 / 语义 |
| --- | --- |
| `RAG_EMBEDDING_PROVIDER` | `siliconflow`；显式 `simple` 仅用于旧索引/离线测试 |
| `RAG_EMBEDDING_BASE_URL` | `https://api.siliconflow.cn/v1` |
| `RAG_EMBEDDING_MODEL` | `BAAI/bge-m3` |
| `RAG_EMBEDDING_API_KEY` | 用户本地填写，初始为空，无默认或 LLM 密钥继承 |
| `RAG_EMBEDDING_DIMENSION` | `1024`，用于响应/索引校验，不发给 BGE-M3 API |
| `RAG_EMBEDDING_REVISION` | `siliconflow-bge-m3-v1`，项目管理的版本标签 |
| `RAG_EMBEDDING_TIMEOUT_SECONDS` | `20`，每次 HTTP 请求超时 |
| `RAG_EMBEDDING_MAX_RETRIES` | `2`，首次请求之外最多两次 |
| `RAG_EMBEDDING_BATCH_SIZE` | `8`，初始保守批量上限 |

`REVISION` 是本地可审计标签，不冒充平台保证的不可变权重版本。云端模型若
不提供固定修订号，需要固定文本探针和检索回归检测变化，再决定是否重建。

创建配置段后先保持旧 provider；用户只填写 API Key。验证和重建完成前不将
运行部署切到新 provider，不通过重启偷偷启用。现有 `LLM_*` 全部保留。
对尚无新配置的旧部署，兼容原来的 simple 行为并明确标记“测试嵌入”；
一旦 registry 激活真实模型，配置缺失或无效必须失败，不能借兼容路径回退。
密钥不进入命令行参数、日志、报告、Git、截图或异常响应。配置探测只报告
“已设置/未设置”，不报告密钥的前后缀。首次联网只用内置公开测试句子。

采用云端方案意味着：文档切片和文档检索问题会传给硅基流动；接口不需要
上传文件、文件名、user ID、历史问答或学习笔记。默认不传这些附加信息。

## 5. 组件与依赖边界

- RAG 专用配置/工厂负责建立不可变的 `EmbeddingProfile` 和客户端；
  不让旧的全局 Memory 单例读取这些环境变量。
- 嵌入接口区分 `embed_documents(list[str])` 与 `embed_query(str)`，
  BGE-M3 使用相同文本请求，不添加其他模型专用前缀或指令。
- Qdrant 与 JSON RAG 从同一个 profile 获取维度、模型身份和向量，
  文档向量与问题向量不能分别选取模型。直接文档处理辅助入口也须纳入检查。
- Provider 适配器只负责网络协议与结果验证，不读写用户文件或 Qdrant。
- 索引身份/迁移服务负责 manifest、状态机、重建与验证；迁移管理命令
  与交互式用户请求分离，不暴露成普通用户可访问的跨用户 API。
- 沿用 UI → Assistant → Tool → RAG/Storage 依赖边界，避免底层导入 UI。

## 6. 网络与错误契约

请求使用 HTTPS `POST /embeddings`、Bearer 密钥、`model`、文本列表和
`encoding_format=float`。BGE-M3 固定 1024 维，不能发送仅部分 Qwen 模型
支持的 `dimensions` 参数。拒绝带 user-info/query/fragment 的 Base URL；
生产配置不接受 HTTP，不自动跟随重定向传递密钥。

每条输入必须为非空文本；沿用现有切片，另加每条 6000 UTF-8 字节的应用层
保守上限。这不是将字节数冒充 token 数。超限明确报错并要求调整切片；
查询超限提示用户缩短，不静默截断。批次不跨用户合并，无跨租户内容缓存。

每进程最多两个并发嵌入请求。429、连接/超时、502/503/504 可有界重试；
401/403、400、404、异常响应结构不重试。指数退避带小幅抖动，尊重可解析的
Retry-After，但单次等待最多 10 秒，整个批次的重试预算最多 75 秒。
不叠加 SDK 隐式重试，不用无限等待掩盖免费服务限流。

响应按 `index` 恢复输入次序；缺项、重复 index、越界、响应模型不符、
维度不为 1024、非有限数值、零向量均拒绝。统一 L2 归一化，算法版本计入
profile。不得补零、截断、不告知地换模型或回退到 SimpleEmbedding。

所有文档 chunks 成功嵌入并验证后才进入原有存储提交过程；中途失败不删除
原文档索引，不将半批响应作为成功结果。界面沿用可理解的失败/重试状态，
只记录状态码、耗时和安全的请求追踪 ID，不保存提供商原始错误正文。

远端嵌入临时不可用不等于容器需要重启；五分钟基础健康巡检不能因此循环
重启 App。外部模型连通性归专门探测和 deep smoke，基础存活保持独立。

## 7. 索引身份与兼容性

Profile 的规范化内容包括 provider、endpoint origin/path、model、revision、
dimension、归一化版本、文档/查询预处理版本、切片策略版本和向量距离。
不包含密钥。以规范化 JSON 的 SHA-256 作 fingerprint。

新物理集合采用 `<base>__<fingerprint前16位>`，校验总长度不超过 255；
manifest 保存完整 fingerprint，前缀碰撞仍拒绝。保留现有命名空间及
document_id 过滤；不把“集合按版本分开”当成租户隔离的替代品。

在应用持久化数据目录下维护 `vector_indexes/rag/` registry，记录当前
激活的 profile、物理集合、源索引、迁移 ID、验证结果和状态。目录包含在
既有 App 数据备份中；不放进临时 worktree。每个新 point 的系统 metadata
也记录 fingerprint，外部文档 metadata 不能覆盖此字段或隔离字段。

启动和查询要求配置、registry、物理集合身份/维度一致；不一致明确失败，
不创建一个空集合让用户误以为旧文档丢失。空的新部署通过显式初始化命令
建立空索引；旧非空无身份索引只能作为迁移源，不能猜测其属于新模型。

JSON RAG 也记录 profile，按版本保存新缓存；保留旧文件，不自动覆盖。
移除真实模型路径的补零/截断和不兼容缓存错误吞噬。旧 `simple` 配置可
显式读取原格式，错误数据不能被伪装成“没有文档”。

## 8. 重建、切换与回滚

流程：`planned → building → validated → active`；失败为 `failed`，记录
可恢复检查点，不把部分结果标为 validated。

### 盘点和重建

1. 只读盘点实际源集合/JSON、逐用户/逐文档 chunk 数、源内容与 metadata
   摘要及空间需求；不依赖之前“空库”的历史结论。
2. 迁移前调用现有一致性冷备份。Windows 控制器使用相同 operations lock，
   与备份/更新/巡检互斥；暂停 App 写入及导入任务，在维护窗口重建。
3. 从源 payload 或 JSON 中逐页读取原 chunk 内容，保留 ID、文档版本、
   来源、namespace。源 ownership 不明、内容缺失或元数据冲突时失败关闭。
   不用内存中无界 `scroll` 汇总整个库；管理路径新增有界分页读取。
4. 写入全新目标；检查点包含源 fingerprint、profile、已完成分区/游标和
   验证摘要。批次可幂等重复，恢复必须确认源摘要未变。
5. 外部失败、进程中断、磁盘不足只影响未激活目标；源索引不修改。
   若控制器崩溃后 App 被恢复，重新开始前必须复核源变化，不能盲目接着写。

### 验证和切换

逐用户/逐文档核对 ID 集合、chunk 数、内容/来源摘要及向量身份，验证没有
跨用户/跨文档命中。profile、点和检查点全部匹配后执行检索质量门禁。

切换在 App 停止时进行，保留旧配置和索引；更新 registry 与本地环境中的
RAG 配置，再启动应用。两个文件不能假定存在跨文件原子事务：用持久化
切换日志标明准备/完成状态，启动发现不完整状态时拒绝开放 RAG 写入，恢复
命令可确定地回到旧配对状态。维护锁释放前执行冒烟验证。

验证失败则保持或恢复旧配对；旧模型的文档召回只作为既有服务回退能力，
不能称为真实嵌入已经上线。不得自动删除源集合、旧缓存、备份或迁移结果。

### 回滚的长期约束

只有确认切换后没有文档变更时，才能快速切回旧索引。若已有新增、修改或
删除，必须从最新权威 chunk 状态按旧 profile 重建一个新的回滚索引并验收，
不能简单切回过期集合导致数据丢失/删除记录复活。无法重建时保持维护状态并
报告原因；不恢复整个旧数据库而覆盖 Notes 或其他新业务数据。

模型、维度、预处理或切片规则变化均走同一版本化过程，即使维度相同也一样。
API Key 轮换不改变 profile，不要求重建。

## 9. 验收标准

- 离线单测覆盖配置隔离、空密钥、HTTPS/重定向、正确请求体、乱序响应、
  错误维度、NaN/Infinity/零向量、429/401、超时重试预算和日志脱敏。
- JSON/Qdrant 两条路径验证旧索引拒绝混用、同维不同模型拒绝、持久化重启、
  迁移断点恢复、源变化拒绝、切换日志恢复和有新数据时的回滚保护。
- 保留用户、文档、来源与版本；重建后每个分区数量和内容摘要必须 100% 一致。
- RAG 与 Memory 的模型配置隔离测试：填入 RAG 密钥不能让 Memory 发起网络请求。
- 新增固定的公开/合成中英文检索集：至少 20 个有答案问题，10 中文、10 英文，
  固定文档/预期 chunk；Recall@5 至少 0.90，MRR@5 至少 0.75，并不低于旧模型
  在同一集上的结果。另有跨用户/跨文档负例，错误命中必须为零。
- 用户填写本地密钥后先做无敏感内容的真实嵌入探测，再做隔离数据的
  `deploy/smoke_test.py --deep`；测试不得枚举或删除业务用户，清理仅限本次测试
  明确创建的记录。未做真实验证时必须标记未验证。
- 使用稳定目录 `venv` 执行相关 memory/RAG、QA、Notes、导入与部署回归。
  通过测试、完成稳定目录集成并实际验证后，才报告“接入完成”。
