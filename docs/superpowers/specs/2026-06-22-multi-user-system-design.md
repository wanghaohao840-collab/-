# 多用户系统设计

## 目标

为智能文档学习助手增加本地多用户系统，使每个用户拥有相互隔离的文档库、学习笔记、问答历史、学习报告和记忆系统，并为以后迁移 PostgreSQL、对象存储、Qdrant 或 API 服务保留清晰边界。

第一版使用本地 SQLite 注册登录。用户名唯一，不做邮箱验证、密码找回、管理员或角色权限。

## 方案选择

采用混合隔离方案：

- SQLite 管理用户身份、报告索引和旧数据迁移状态。
- 每个用户以不可变 UUID 作为内部身份和数据目录名。
- 现有 RAG、学习历史和报告文件迁入用户专属目录。
- Gradio 的每个浏览器会话持有独立的登录状态和 Assistant 实例。
- 存储路径由专门的用户存储服务生成，业务代码不直接拼接任意用户路径。

不采用仅用用户名拼 JSON 文件名的最小方案，因为它无法提供可靠身份认证，且用户名变更、路径安全和并发访问风险较高。暂不将全部 chunks、笔记和记忆关系化，因为这会在本阶段重写现有 RAG 持久化链路，超出实现多用户隔离所需范围。

## 架构边界

保持现有依赖方向：

```text
Gradio UI
  -> Authentication / Session
  -> PDFLearningAssistant
  -> MemoryTool / RAGTool
  -> Memory / RAG / Storage
```

身份边界遵循以下规则：

1. 登录成功后，服务端会话保存用户 UUID、用户名和该会话的 Assistant。
2. 业务操作只能从服务端会话取得用户 UUID，不接受界面自行提交的 `user_id`。
3. 未登录会话不能访问上传、检索、问答、笔记、记忆、报告或删除操作。
4. 用户名仅用于登录和展示；数据归属始终使用不可变 UUID。
5. 所有数据读取、写入、下载和删除都必须重新应用当前用户作用域。

## 组件职责

### 认证服务

认证服务负责注册、登录和读取用户身份：

- 创建 UUID 用户标识。
- 校验用户名格式和唯一性。
- 使用标准库 `hashlib.scrypt` 和每个账户独立的 16 字节随机盐保存凭证，不保存明文密码。首版参数固定为 `n=16384`、`r=8`、`p=1`、`dklen=32`，编码中保存版本和参数以便以后升级。
- 登录失败统一返回“用户名或密码错误”，不泄露账户是否存在。
- 使用 SQLite 事务维护账户一致性。

第一版会话由 Gradio 会话状态承载，不实现跨应用 JWT、长期令牌或服务器端会话表。

### 用户存储服务

用户存储服务将用户 UUID 映射到固定根目录，并提供受控的子路径。调用方不能提交任意用户目录，也不能通过 `..`、绝对路径或用户名越界访问其他用户数据。

建议目录结构：

```text
data/
├── app.db
├── legacy_backups/
└── users/
    └── <user_uuid>/
        ├── documents/
        ├── rag/rag_cache.json
        ├── history.json
        ├── memory/
        └── reports/
```

上传的原始文档复制到当前用户的 `documents/`。用户可见的原始文件名只用于展示；内部文档 ID 使用 UUID，避免同名文件覆盖。JSON 文件采用临时文件写入后原子替换。

### Assistant 与工具层

`PDFLearningAssistant` 必须由经过认证的用户上下文创建。它向 RAG 和 Memory 工具注入用户专属存储位置和用户 UUID，不再依赖固定的 `user123` 或全局 Assistant。

RAG 操作保留 `document_id` 隔离，并增加不可绕过的用户作用域。文档新增、搜索、问答、总结、统计、删除和清空都只能作用于当前用户的数据。现有 PDF 页码、来源元数据和多格式导入能力继续保留。

学习笔记和问答历史写入当前用户的 `history.json`。每条问答明确保存 `document_id`，删除文档时按结构化字段清理，不再通过路径字符串包含关系猜测归属。

记忆系统由当前用户的 Memory 实例管理，所有记忆元数据包含用户 UUID，持久化后端位于该用户的 `memory/`。搜索、统计、遗忘和清空必须同时受当前用户作用域约束。

### 报告服务

每次生成学习报告都会：

1. 从当前用户的文档、问答、笔记和记忆生成内容。
2. 自动保存 Markdown 快照到当前用户的 `reports/`。
3. 在 SQLite `report_records` 中保存报告 UUID、用户 UUID、标题、相对文件路径和生成时间。
4. 返回报告内容并刷新当前用户的报告历史。

Word 导出可由已保存的报告快照生成，避免稍后导出时内容因学习数据变化而不一致。报告列表、查看和下载都按当前会话用户过滤。

## 数据模型

SQLite 至少包含以下表：

### `users`

- `id`：UUID 文本主键。
- `username`：规范化后的唯一用户名。
- `password_hash`：包含算法参数、随机盐和派生值的密码哈希。
- `status`：第一版为 `active`，保留禁用能力但不提供管理界面。
- `created_at`、`updated_at`：UTC 时间。

### `report_records`

- `id`：报告 UUID 主键。
- `user_id`：外键关联 `users.id`。
- `title`：报告标题。
- `relative_path`：相对于该用户目录的受控路径。
- `created_at`：UTC 时间。

### `data_migrations`

- `id`：迁移记录主键。
- `migration_key`：例如旧版 `user123` 数据集的稳定标识，具有唯一约束。
- `claimed_by_user_id`：认领用户 UUID。
- `status`：`in_progress`、`completed` 或 `failed`。
- `backup_path`：位于受控备份根目录下的相对路径。
- `started_at`、`completed_at`、`error_summary`。

SQLite 开启外键约束。数据库写入使用事务，敏感错误不直接展示给用户。

## 注册、登录与退出流程

注册规则：

- 用户名去除首尾空白并使用 Unicode `casefold()` 生成唯一性键；展示值保留原始大小写。长度为 3～32 个字符，只允许 Unicode 字母、数字、下划线、连字符和点，且首尾必须是字母或数字。
- 密码长度为 8～128 个 Unicode 字符；不强制复杂字符组合。
- 重复用户名返回明确但不包含内部数据库信息的提示。
- 注册成功后可直接建立当前 Gradio 登录会话。

登录规则：

- 验证成功后创建该用户专属 Assistant。
- 验证失败统一返回“用户名或密码错误”。
- 不将密码、密码哈希或用户目录放入前端可编辑字段。

退出规则：

- 清除 Gradio 会话中的用户身份、Assistant 和当前文档状态。
- 返回注册登录视图。
- 退出不删除任何持久化数据。

## Gradio 会话与并发

现有模块级全局 `assistant = PDFLearningAssistant(user_id="user123")` 必须移除。每个 Gradio 浏览器会话通过 `gr.State` 保存独立会话上下文，事件处理函数先验证登录状态，再从会话上下文取得 Assistant。

不同用户写入不同目录，天然隔离。为支持同一用户打开多个浏览器会话，用户历史和 RAG 缓存的读改写操作使用用户级锁，并在写入前重新加载最新版本，避免后写覆盖前写。SQLite 自身负责账户、报告索引和迁移记录的事务并发。

进程内用户锁满足第一版本地单进程 Gradio 部署。多进程或多节点部署时，应将这些 JSON 存储替换为支持并发事务的数据库或外部服务；该升级不属于第一版范围。

## 旧数据认领与迁移

旧数据不会自动归属任何新用户。已登录用户可主动执行一次“认领旧数据”：

1. 检查稳定 `migration_key` 是否已被成功认领。
2. 在 SQLite 事务中创建 `in_progress` 记录。
3. 将旧文件复制到带时间戳的 `legacy_backups/` 目录，不修改原文件。
4. 将旧文档、RAG 缓存、学习历史、记忆和报告转换并复制到认领用户目录。
5. 为缺失的文档生成 UUID，并同步改写 chunks、问答和相关元数据中的 `document_id`。
6. 校验记录数量、文件可解析性和引用关系。
7. 成功后标记 `completed`；失败时删除本次写入的用户侧临时数据、保留备份并标记 `failed`。

唯一迁移键和事务状态确保重复点击不会重复导入。已由其他用户完成认领时，后续用户不能再次认领。

## 删除语义

- 删除当前文档：只删除当前用户、目标 `document_id` 的原始文件、RAG chunks、文档历史和相关问答；学习笔记默认保留。
- 清空全部文档：只清空当前用户的文档、RAG 数据和问答历史；学习笔记、报告快照和账户保留。
- 清空笔记：只清空当前用户的学习笔记，不影响文档、问答、报告和其他用户。
- 删除报告：第一版不提供删除操作；报告历史只读并可下载。
- 删除账户：第一版不提供。

## 错误处理与安全要求

- 密码使用前述 `scrypt` 参数和独立随机盐，比较派生值时使用 `hmac.compare_digest()`。
- 任何路径在使用前都验证解析后的绝对路径位于当前用户根目录内。
- 下载文件通过报告记录或文档记录解析，不接受任意文件路径。
- 用户 A 提供用户 B 的 `document_id`、报告 ID 或文件名时，系统返回当前作用域内不存在，不泄露对象是否属于其他用户。
- JSON 损坏时停止相关写操作并给出可恢复提示，不静默覆盖损坏文件。
- 迁移和报告失败记录安全摘要，界面不显示密码信息、绝对数据目录或堆栈。

## 测试策略与验收标准

所有功能按测试驱动方式实现。核心验收包括：

1. 用户可注册、登录和退出；重复用户名被拒绝，数据库中不存在明文密码。
2. 两个用户上传同名文档后，文档列表、原始文件、RAG chunks 和检索结果完全隔离。
3. 用户 A 无法通过伪造用户 ID、文档 ID、报告 ID 或路径读取、下载或删除用户 B 的数据。
4. 笔记、问答、记忆、统计和报告只包含当前用户的数据。
5. 每次生成报告都会保存不可变 Markdown 快照和报告索引；所属用户可查看并导出 Word。
6. 多个浏览器会话不会共享当前用户或当前文档。
7. 同一用户的并发历史写入不丢失已成功提交的记录。
8. 删除当前文档、清空全部文档和清空笔记符合既有删除语义，且不影响其他用户。
9. 旧数据只能成功认领一次；迁移后的记录和引用完整；失败迁移可安全重试且不留下半成品。
10. 应用重启后账户、文档、问答、笔记、记忆和报告可恢复。
11. PDF、TXT、Markdown、DOCX 导入，PDF 页码引用、总结模式、报告导出等现有能力通过回归测试。

测试分层包括认证与存储单元测试、Assistant/Tool 集成测试、两个用户的端到端隔离测试，以及 Gradio 事件函数的会话状态测试。测试数据全部使用临时目录和临时 SQLite 数据库，不接触工作区中的真实运行数据。

## 范围外事项

第一版明确不包含：

- 邮箱验证、密码找回、管理员、角色和团队空间。
- OAuth、JWT、公开 API 和跨设备长期会话。
- 账户删除、报告删除和用户名修改界面。
- PostgreSQL、对象存储、Qdrant 或多节点部署。
- 对现有 RAG 算法、嵌入模型和报告内容进行无关重构。

这些能力可在现有用户 UUID、认证服务、用户存储服务和仓储边界之上后续扩展。
