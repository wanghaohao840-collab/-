# 知研智能问答 `/qa` 垂直切片设计

**日期：** 2026-08-25

**状态：** 各设计章节已确认，等待书面规格复核

**范围：** `/qa` 产品路由、持久化问答领域、响应式 UI、旧问答迁移、后台总结、安全删除与验收

## 1. 背景

文档库垂直切片已经集成并发布，但 React 中的 `/qa` 仍由 `MigrationPage` 占位。现有后端已经具备可复用的问答能力：

- `PDFLearningAssistant.ask(...)` 支持 1–10 份文档和 `auto`、`joint`、`compare`、`summary` 模式；
- RAG 能返回稳定引用，包括文档、页码、摘录和引用编号；
- 现有上下文预算和 token 估算可以继续使用；
- 导入任务已有持久化领取、恢复、取消和提交模式，可作为后台总结任务的实现参考。

现状同时存在四个产品化缺口：

1. `history.json` 只保存扁平问题记录，不能表达会话、消息状态、重试和多轮上下文；
2. `SummaryTaskManager` 只在内存中保存状态，服务重启后任务丢失；
3. React、旧 Gradio、问答历史和 QA Memory 尚未形成统一持久化边界；
4. 缺少桌面、平板、手机三档真实产品界面和可恢复的失败状态。

本设计建立一个独立但复用现有 RAG 的持久化 QA 领域切片。它必须能在单机 SQLite 中完整工作，同时为未来 PostgreSQL、任务队列、多实例 worker 和 SSE 留出稳定边界，但不在本阶段实现通用事件溯源或分布式基础设施。

## 2. 目标

### 2.1 产品目标

- 将 `/qa` 从迁移占位页替换为真实 React 产品路由；
- 支持创建、切换、查看最近会话、自动命名和永久删除；
- 支持普通问答、联合问答、文档对比和多文档总结；
- 在回答旁展示可复制、可追溯的引用依据；
- 在刷新、断线、模型失败和服务重启后提供明确且可恢复的状态；
- 让 React 和旧 Gradio 通过同一个 `QaService` 写入同一份问答数据；
- 满足用户隔离、CSRF、安全错误、删除不复活和日志最小化要求。

### 2.2 长期演进目标

- 领域模型通过显式版本和迁移演进，不依赖临时 JSON 结构；
- RAG、持久化、后台执行和传输层通过小而稳定的接口隔离；
- 状态查询 API 可在未来直接作为 SSE 事件来源；
- worker 使用租约和幂等提交语义，后续可迁移到独立进程或消息队列；
- 删除流程能够跨数据库、QA Memory、向量库和文件存储安全重试；
- 设计避免没有当前消费者的通用抽象。

## 3. 非目标

本切片不包含：

- SSE、WebSocket 或逐 token 流式输出；
- 会话分享、多人协作、文件夹、手动排序或手动改名；
- 用户可修改已有会话的文档范围；
- 通用事件溯源框架或新的 RAG 实现；
- PostgreSQL、Redis、消息队列或多节点部署；
- 学习笔记、学习洞察、文献检索和学习中心的具体实现。

这些能力属于后续独立规格；本设计只保证迁移边界稳定。

## 4. 已确认的核心决策

1. 普通、联合和对比问答使用同步 HTTP 请求；多文档总结使用持久化后台任务。
2. 问答历史升级为完整的会话、消息和引用快照模型。
3. 第一版包含会话创建、切换、最近列表、自动标题和永久删除。
4. 会话的文档范围在创建时固定；切换文档必须创建新会话。问答模式可逐条消息变化。
5. 多轮上下文由“持久化滚动摘要 + 摘要边界后的完整消息”组成；原始消息永不因摘要生成而删除。
6. 删除会话永久清除其消息、引用、摘要、后台任务和相关 QA Memory。
7. 删除文档安全级联清除所有引用该文档的 QA 会话和衍生数据。
8. 当前使用 REST 状态查询；数据模型和状态边界必须允许未来增加 SSE 而无需迁移历史数据。
9. 同一会话同一时间只允许一个生成操作；不同会话可以并行。
10. 旧扁平问答不能被伪造成多轮对话，因此每条旧记录迁移为一个独立的单轮会话。

## 5. 总体架构

```text
React QaPage
    │  /api/v1/qa/*
    ▼
FastAPI QA Router
    ▼
QaService ───────────────► QaRepository ───► SQLite
    │                            │
    │                            └──────────► deletion fences / job state
    ├────────► QaAnswerEngine ──────────────► existing Assistant + RAG
    └────────► QaJobWorker ─────────────────► durable summary execution

Legacy Gradio ───────────► QaService
```

### 5.1 边界职责

- **QA Router**：认证上下文、CSRF、请求解析、HTTP 状态和安全 DTO；不包含业务事务。
- **QaService**：用户与文档归属校验、会话不变量、状态转换、幂等、上下文组装、删除协调和响应组装。
- **QaRepository**：SQLite 查询和短事务；不调用模型、向量库或文件系统。
- **QaAnswerEngine**：将现有 Assistant/RAG 适配为请求级 `AnswerResult`，一次性返回回答、引用和元数据。
- **QaJobWorker**：后台总结任务的领取、心跳、取消、重试、恢复和条件提交。
- **SessionRegistry**：继续提供唯一的用户运行时身份和现有 Assistant；不得为 QA 创建第二套用户目录或第二套 RAG 会话。

模型调用、检索和文件操作均在数据库事务外执行。最终结果只通过带状态和版本条件的短事务提交。

### 5.2 请求级回答结果

现有 `_last_action_data` 是可变的运行时状态，不能作为并行请求之间的长期边界。`QaAnswerEngine.answer(...)` 必须返回请求局部的值对象：

```text
AnswerResult
- answer
- sources[]
- mode
- token/latency metadata
- structured comparison payload (optional)
```

回答和引用必须在同一次调用中绑定，禁止在另一请求可能运行后再读取共享的“最后一次结果”。验收测试必须证明并发会话之间不会串用引用。若底层 Assistant 在改造期间仍有共享可变状态，应使用最小范围的每用户执行锁作为过渡保护；目标实现仍需提供请求级结果接口。

## 6. 领域规则与数据模型

### 6.1 领域不变量

- 每个会话属于且只属于一个用户；所有读取和写入都同时限定 `user_id`。
- 会话包含 1–10 份已就绪且归当前用户所有的文档。
- 会话创建后不得增加、删除或重排文档。
- `compare` 至少需要两份文档。
- 消息内容和引用快照属于会话，不能跨会话复用。
- 同一会话只允许一个 `pending` 问答或活动总结任务。
- 跨用户访问统一返回 404，不泄露资源是否存在。
- 已建立删除栅栏的资源不得接受新的读取、生成或提交。

### 6.2 `qa_conversations`

保存：

- `id`、`user_id`；
- `title` 和 `origin`（`product`、`legacy_json`、`legacy_gradio`）；
- 当前滚动摘要、`summary_through_message_id`、`summary_version`；
- 用于条件更新的 `version`；
- `created_at`、`updated_at`、`last_message_at`。

会话采用硬删除，不通过普通软删除状态继续暴露内容。删除过程所需的非内容栅栏独立保存。

### 6.3 `qa_conversation_documents`

保存：

- `conversation_id`、`user_id`；
- `document_id`、`document_name_snapshot`；
- `position`。

唯一约束覆盖会话和文档，外键随会话级联删除。名称快照用于历史显示；创建和提问时仍需校验真实文档归属与就绪状态。

### 6.4 `qa_messages`

保存：

- `id`、`conversation_id`、`user_id`、`turn_id`；
- `role`（`user`、`assistant`）；
- `status`（`pending`、`completed`、`failed`、`cancelled`）；
- `mode`、正文、`source_state`；
- `client_request_id`、`retry_of_message_id`；
- 安全错误码和追踪 ID；
- `version`、创建、更新和完成时间。

`client_request_id` 在当前用户和会话内唯一。`source_state` 至少区分 `available`、`none` 和 `legacy_unavailable`。

### 6.5 `qa_message_sources`

针对已完成的助手消息保存不可变快照：

- 显示顺序和 `citation_id`；
- 文档 ID、文档名称、页码或章节；
- 摘录、引用文本、`truncated`；
- 来源类型（RAG 或 GraphRAG）。

引用快照保证检索索引变化后历史回答仍可解释；当文档被删除时，这些快照随相关会话安全级联删除。

### 6.6 `qa_jobs`

保存多文档总结任务：

- 会话、用户、输入消息和目标助手消息；
- `queued`、`running`、`completed`、`failed`、`cancelled` 状态；
- 阶段、进度、取消请求、尝试次数；
- worker 租约拥有者、租约期限和心跳；
- 安全错误码、追踪 ID和各阶段时间戳。

数据库约束和领取事务共同保证一个任务只有一个有效提交者，并保证一个会话最多有一个活动生成任务。

### 6.7 `qa_deletion_fences`

保存不含用户正文的删除协调信息：

- 删除 ID、用户 ID、目标类型和随机资源 ID；
- 状态、尝试次数、安全错误码；
- 创建、更新时间和完成时间。

它同时是删除栅栏和可恢复任务记录。内容删除完成后可按运维保留策略清理；不得保存问题、回答、摘录、路径或文档正文。

### 6.8 `qa_legacy_imports`

按用户保存旧历史来源摘要、迁移版本、导入数、跳过数和完成时间。它保证迁移可重复执行而不会产生重复会话。

## 7. 多轮上下文

每次提问的上下文按以下顺序组装：

1. 会话固定文档范围；
2. 已持久化的滚动摘要；
3. 摘要边界之后的最近完整问答；
4. 当前问题。

上下文继续使用现有模型窗口、输出保留和安全余量计算。当前问题必须被完整保留；较旧的完整问答先被滚动摘要替代。

当摘要边界后的 token 数超过阈值时，服务在回答成功后异步计算新摘要。摘要在事务外生成，并仅在会话版本和摘要边界仍匹配时条件提交。摘要失败不会让当前或下一次问答失败；系统回退到预算内的最近完整消息并记录指标。所有原始消息仍保存在 `qa_messages` 中。

## 8. API 设计

所有接口位于 `/api/v1/qa`。

### 8.1 会话

- `POST /conversations`：以 1–10 个文档 ID 创建固定范围会话。
- `GET /conversations?cursor=&limit=`：按最近活动时间游标分页。
- `GET /conversations/{id}`：返回会话、文档范围和当前活动状态。
- `GET /conversations/{id}/messages?cursor=&limit=`：游标分页返回消息和引用快照。
- `DELETE /conversations/{id}`：建立删除栅栏并返回 `202`；资源立即从当前用户界面隐藏，后台完成硬删除。

第一条有效问题经过空白归一化后截取最多 40 个 Unicode 字素作为自动标题。标题生成不调用模型。

### 8.2 普通、联合和对比问答

`POST /conversations/{id}/messages` 接收：

- `question`；
- `mode`（`auto`、`joint`、`compare`）；
- `client_request_id`。

服务先在短事务中创建用户消息和 `pending` 助手消息，再在事务外执行 RAG，最后条件提交回答和引用。

- 首次完成或重复查询到已完成结果时返回 `200`；
- 重复查询到仍在处理的相同请求时返回 `202` 和消息 ID；
- 模型或服务失败时持久化 `failed`，返回安全错误码和可恢复消息 ID；
- 同一会话已有其他活动生成时返回 `409 QA_CONVERSATION_BUSY`。

`GET /messages/{id}` 用于刷新、断线或超时后的状态恢复。

`POST /messages/{id}/retry` 仅接受当前用户可重试的失败助手消息。它保留原失败记录，创建新的助手消息，并设置 `retry_of_message_id`。

### 8.3 多文档总结

- `POST /conversations/{id}/summary-jobs`：创建持久化总结任务并返回 `202`；
- `GET /jobs/{id}`：返回状态、阶段、进度和安全错误；
- `POST /jobs/{id}/cancel`：请求取消。

总结结果作为 `mode=summary` 的正常消息进入会话，因此可以使用同一套历史、引用和未来 SSE 传输边界。

### 8.4 删除状态

`GET /deletions/{id}` 返回最小化的删除状态。前端通常无需等待即可离开资源，但可以在全局通知或运维流程中确认完成。

### 8.5 安全 DTO

响应不得包含用户 ID、运行时目录、文件存储路径、提示词、模型密钥、原始异常或其他用户资源标识。所有写接口执行现有认证和 CSRF 约束。

## 9. 关键流程

### 9.1 创建和提问

1. 用户从文档库“开始问答”或 `/qa` 的新建入口选择文档；
2. 服务校验用户、文档归属、就绪状态和数量后创建会话；
3. 第一条提问写入消息对并锁定当前会话生成槽；
4. `QaAnswerEngine` 在事务外执行检索和生成；
5. 服务在删除栅栏、消息状态和版本仍匹配时提交回答与引用；
6. 提交成功后更新会话活动时间，并按阈值安排滚动摘要；
7. QA Memory 写入携带会话和消息 ID，便于之后精确删除。Memory 写入失败不回滚已完成回答，但必须可观测和可补偿。

### 9.2 断线和重启

- HTTP 断线不删除已持久化消息；客户端使用消息 ID恢复状态；
- 服务启动时把遗留的同步 `pending` 消息标记为 `failed`，错误码为可重试的服务中断；
- 总结 worker 重新领取租约已过期的 `running` 任务，直到达到有限重试上限；
- 幂等键保证客户端重发不会触发第二次模型调用。

### 9.3 取消竞态

- `queued` 任务可直接转为 `cancelled`；
- `running` 任务记录取消请求，worker 和模型回调在关键阶段检查；
- 即使模型已经返回，条件提交前仍需检查取消和删除栅栏；
- 已完成结果不会被后到的取消请求改写。

### 9.4 安全删除

删除会话或文档时：

1. 在短事务中建立删除栅栏，使资源立即不可读、不可生成；
2. 请求取消进行中的问答和总结；
3. 删除相关 QA 会话、消息、引用、滚动摘要和任务；
4. 删除带有会话或消息关联 ID 的 QA Memory；
5. 文档删除继续清理相关向量和文件；
6. 全部步骤成功后把栅栏标记完成，失败步骤可幂等重试。

所有生成结果在提交前检查栅栏和目标消息存在性，因此删除后不会被迟到回调复活。文档删除确认框必须显示受影响的 QA 会话数量，并明确其不可恢复性。

## 10. 旧历史与 Gradio 迁移

### 10.1 `history.json`

- 迁移按用户运行，并由 `qa_legacy_imports` 记录来源摘要和版本；
- 每条有效旧问答迁移为一个 `origin=legacy_json` 的独立单轮会话；
- 文档集合从旧记录快照恢复并按稳定顺序固定；
- 旧数据没有引用快照时设置 `source_state=legacy_unavailable`，UI 显示“旧记录未保存引用依据”；
- 无法验证用户或文档范围的记录不会被伪造，计入跳过数并写安全诊断；
- 迁移成功后旧文件保留一个发布周期用于回滚读取，但产品路径停止写入其 `questions[]`。

### 10.2 旧 Gradio

Gradio 问答处理器改为调用 `QaService`，不再直接负责历史写入。若旧界面没有会话 ID，每次提交创建一个 `origin=legacy_gradio` 的独立单轮会话；不得假装存在旧界面未提供的多轮上下文。报告和统计读取 `QaRepository`，避免新旧数据分叉。

底层 Assistant 的产品调用改为无历史副作用的生成接口；任何保留的兼容入口不得继续向 `history.json` 写新问题。

## 11. 响应式产品界面

视觉方向已经通过三档线框确认，并沿用现有知研设计 token。

### 11.1 桌面（`>= 1200px`）

常驻四个逻辑区域：

1. 现有应用导航；
2. 最近会话列表和“新建问答”；
3. 对话、固定文档提示和输入区；
4. 当前回答的引用依据。

引用点击可定位对应卡片；复制操作提供非阻塞反馈。总结入口位于会话头部，运行时显示阶段、进度和取消操作。

### 11.2 平板（`768–1199px`）

保留压缩后的应用导航和完整对话区。会话列表和引用依据使用互斥侧抽屉；抽屉捕获焦点、Escape 关闭并把焦点返回触发按钮。

### 11.3 手机（`< 768px`）

对话为单列主界面，使用现有 64px 产品底部导航。会话、文档范围和引用依据使用底部抽屉；输入区不被底部导航或系统安全区遮挡。

### 11.4 必备状态

- 无会话、无可用文档、文档未就绪；
- 正在回答、回答完成、失败可重试；
- 总结排队、运行、取消中、已取消和失败；
- 无引用、旧记录无引用、引用复制成功；
- 会话忙、网络断开、刷新恢复；
- 删除确认、删除处理中和删除失败通知。

所有操作支持合理的键盘顺序、可见焦点、ARIA 状态播报、Escape 关闭抽屉和至少 44px 的移动端触控目标。

## 12. 错误、安全与可观测性

### 12.1 安全错误

前端只接收稳定错误码、用户可执行提示和追踪 ID。至少覆盖：

- `QA_DOCUMENT_NOT_READY`；
- `QA_COMPARE_REQUIRES_MULTIPLE_DOCUMENTS`；
- `QA_CONVERSATION_BUSY`；
- `QA_ENGINE_UNAVAILABLE`；
- `QA_REQUEST_INTERRUPTED`；
- `QA_JOB_CANCELLED`；
- `QA_RESOURCE_DELETING`。

跨用户资源统一 404。未知异常不得返回内部路径、堆栈、提示词、供应商响应或密钥。

### 12.2 日志和指标

结构化日志只记录请求、会话、消息、任务和追踪关联 ID，以及状态转换、持续时间和安全错误码。默认不记录问题、回答、引用摘录或文档正文。

指标至少包括：

- 问答和总结延迟、成功率和失败率；
- 任务排队时间、租约恢复、重试和取消；
- 幂等命中和会话忙冲突；
- 摘要更新失败与上下文回退；
- 删除任务重试和未完成数量；
- QA Memory 补偿失败。

## 13. 测试策略

### 13.1 后端

- 领域单元测试：固定文档范围、标题、状态机、上下文边界、幂等和重试；
- Repository：事务回滚、分页、引用快照、跨用户 404、级联删除和迁移幂等；
- Service/API：普通、联合、对比、总结、CSRF、限制、安全错误和 DTO；
- Worker：领取、租约、心跳、恢复、有限重试、取消竞态和单次提交；
- 并发：同会话互斥、跨会话隔离、引用不串用、删除后结果不复活；
- 故障注入：模型失败、进程重启、数据库冲突、租约丢失和跨存储删除失败。

模型和 RAG 在确定性测试中通过 `QaAnswerEngine` fake 隔离；另保留配置完整时的本地真实 RAG smoke。

### 13.2 前端

- 会话创建、切换、分页、标题和永久删除；
- 固定文档范围、模式选择、消息状态和失败重试；
- 引用面板、复制反馈、总结进度和取消；
- 桌面四区、平板侧抽屉和手机底部抽屉；
- 键盘、焦点返回、ARIA 播报和移动触控目标。

### 13.3 E2E 与兼容性

E2E 覆盖：从文档库选择已就绪文档、创建会话、普通问答、文档对比、引用查看、刷新恢复、总结取消和安全删除。

兼容性测试证明：

- 同一 `history.json` 重启后不会重复迁移；
- 旧 Gradio 问答进入新 Repository；
- 产品路径不再写入旧 `questions[]`；
- 旧报告和统计切换后结果仍正确。

## 14. Penpot 与实现核对

- Desktop：`QA / Default`、`QA / Summary running`、`QA / Delete confirm`；
- Tablet：`QA / Conversation drawer`、`QA / Sources drawer`；

画板复用现有颜色、排版、间距、圆角、阴影、焦点和响应式 token。实现完成后用三档运行截图与 Penpot 画板核对；设计和代码差异必须在最终验收记录中解释或修正。

## 15. 发布、回滚与长期迁移

### 15.1 发布顺序

1. 数据库表和幂等旧历史迁移；
2. `QaRepository`、`QaAnswerEngine` 和 `QaService`；
3. 总结 worker、恢复和删除栅栏；
4. API 与 React 三档界面；
5. Gradio、报告和统计切换；
6. Penpot 核对、完整测试和 Docker Linux 验收。

### 15.2 回滚

- 迁移只新增数据库结构，不覆盖旧 `history.json`；
- 旧文件在一个发布周期内保留为只读回滚来源；
- 新 `/qa` 可通过路由级发布开关暂时退回迁移说明页，但不能恢复双写；
- 已完成的新问答数据留在 SQLite，重新启用功能后继续可用；
- 任何 schema 变更必须使用向前迁移，禁止通过删除用户数据回滚。

### 15.3 未来演进

- SQLite Repository 可替换为 PostgreSQL 实现，服务接口和 API DTO 不变；
- `QaJobWorker` 的领取接口可映射到消息队列，任务 ID和条件提交语义不变；
- SSE 可从现有消息和任务状态发布事件，REST 查询继续保留为恢复基线；
- 企业保留策略可扩展删除栅栏的最小审计期限，但不能恢复已删除内容；
- 后续学习笔记、学习洞察和学习中心只通过公开 QA 领域接口引用会话或消息，不直接读取内部表。

## 16. 完成标准

本垂直切片仅在以下条件全部满足后完成：

1. `/qa` 是真实 React 产品路由，不再使用 `MigrationPage`；
2. React 与旧 Gradio 共用 `QaService` 和同一份数据；
3. 普通、联合、对比、持久化总结和引用快照形成完整闭环；
4. 多轮滚动摘要失败不会阻断问答，原始消息完整保留；
5. 用户隔离、CSRF、删除不复活和日志不泄露通过专项测试；
6. Python、React、E2E、npm audit 和 Docker Linux 本地验收全部通过；
7. Penpot 三档画板与实现截图完成核对；
8. API、迁移、恢复、删除和运维说明进入项目文档；
9. 最终集成评审确认没有未解释的设计偏差或用户数据风险。
