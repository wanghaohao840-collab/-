# 知研 QA 重连与长历史设计规格

## 目标

修复 `/qa` 最终集成评审发现的两个长期产品缺口：长对话必须优先显示最新消息并可按需读取更早历史；浏览器刷新或重新进入对话后必须从服务端重新发现正在运行的摘要任务，恢复进度、取消入口与操作互斥。

本设计保持 SQLite 持久化、现有任务状态机、资源 ID、1500 ms 轮询和单 `ApplicationServices` 生命周期不变，为后续 SSE/WebSocket 或分布式任务通知保留稳定资源边界。

## 已选择方案

采用“服务端最近页 + 有界无限查询 + 活动任务发现”方案：

- 保留 `QaRepository.list_messages()` 的既有最早优先语义，避免影响上下文构建、报告和 worker。
- 新增独立的最近消息分页接口。首屏查询最新一页，每页内部仍按时间正序渲染；游标继续加载更早记录。
- 对话列表使用现有最近优先游标，通过明确的“加载更多对话”操作按需扩展。
- 新增用户与对话双重作用域的活动摘要查询。React 在加载或切换对话时从服务端发现 `queued/running` 任务，不把组件内存或浏览器存储当作事实源。
- 摘要创建后立即缓存服务端返回任务；刷新后由活动任务发现恢复任务 ID，再由现有任务状态资源继续轮询。

没有采用以下方案：

- 自动读取全部历史页：实现较少，但数据量随使用时间线性增长，不能作为长期产品默认行为。
- 使用 `sessionStorage/localStorage` 保存任务 ID：无法跨设备、跨会话或清理浏览器状态恢复，并会形成第二事实源。

## 后端架构

### 最近消息分页

`QaRepository` 新增：

```python
list_recent_messages(
    user_id: str,
    conversation_id: str,
    *,
    cursor: str | None = None,
    limit: int = 50,
) -> QaMessagePage
```

规则：

- 所有查询包含 `user_id`、`conversation_id` 和现有删除栅栏条件。
- 数据库按 `created_at desc, id desc` 选择最近记录。
- 首次返回最新一页；后续游标使用严格小于 `(created_at, id)` 的记录读取更早页。
- 返回给调用者前反转单页，使每页内部保持全局时间正序。
- `next_cursor` 由当前页最早记录生成，表示“继续向更早加载”。
- 相同时间戳使用 ID 作为稳定分界；页间不得重复或遗漏。
- 既有 `list_messages()` 不修改。

`QaService.list_messages()` 与现有 REST 消息列表切换到最近页语义。该 API 当前唯一产品消费者是 React；内部完整历史读取继续直接使用既有仓库接口。

### 活动摘要发现

`QaJobRepository` 新增：

```python
get_active_for_conversation(
    user_id: str,
    conversation_id: str,
) -> QaJob | None
```

只返回 `queued/running` 任务，并验证所属对话未被删除栅栏隐藏。`QaService.get_active_job(session_token, conversation_id)` 先验证当前会话所有权，再调用仓库。

新增只读端点：

```text
GET /api/v1/qa/conversations/{conversation_id}/summary-jobs/active
```

返回：

```json
{"job": null}
```

或：

```json
{"job": {"job_id": "...", "status": "running", "progress": 40}}
```

无活动任务不是错误；不存在、跨用户或已栅栏化的对话继续返回安全 `404`。响应不得暴露用户 ID、租约、Memory ID、路径、提示词或原始错误。

## 前端数据流

### 游标查询

对话和消息改用 TanStack `useInfiniteQuery`：

- 对话每页 20 条，页面顺序保持最近优先。
- 消息每页 50 条，初始页为最新消息；加载的消息页按“更早页 → 最近页”展开，最终数组全局时间正序。
- 根查询键保持 `['qa','conversations']` 与 `['qa','messages',conversationId]`，现有失效逻辑继续有效。
- 轮询条件扫描所有已加载消息页；任何最新页中的 `pending` 消息都能触发轮询。
- UI 只在 `hasNextPage` 为真时展示“加载更多对话”或“加载更早消息”，用户主动触发，不自动读取全部历史。

新 API 函数必须对游标和路径参数使用 `encodeURIComponent`，并继续传递 `AbortSignal`。

### 摘要恢复与互斥

新增活动摘要查询键：

```ts
['qa', 'active-summary', conversationId]
```

页面的当前任务 ID 按以下优先级确定：

1. 当前用户动作刚创建、且属于所选对话的服务端任务；
2. 活动摘要发现返回的任务；
3. 无任务。

切换对话时清除上一对话的临时任务身份。刷新后没有临时状态，活动摘要查询恢复任务 ID。现有 `useQaJob` 继续轮询具体任务；任务终态后失效活动摘要、消息和对话查询。

以下任一条件成立时，当前对话视为忙碌：

- 问答或摘要创建 mutation 正在提交；
- 已加载消息包含 `pending`；
- 活动/当前任务状态为 `queued` 或 `running`。

忙碌时禁用提问、生成摘要与重复提交，但仍允许切换其他对话和取消当前摘要。取消及终态完成后，通过服务端资源重新协调并恢复操作。

## 失败与并发语义

- 活动任务发现与任务完成竞态：发现后任务可能立即终态；具体任务 GET 返回终态并触发失效即可，不回退到浏览器猜测。
- 刷新发生在摘要完成之后：活动查询返回 `null`，消息最近页包含已完成摘要，界面不显示虚假运行状态。
- 分页期间产生新消息：根查询失效或 pending 轮询重新获取最近页；按消息 ID 去重，保持稳定顺序。
- 跨用户活动任务查询：与现有 QA 资源一致，无法区分“不存在”和“不属于当前用户”。
- 删除栅栏优先：已栅栏化对话无法继续发现任务或消息，晚到状态不得恢复界面资源。

## UI 与可访问性

- “加载更多对话”和“加载更早消息”使用现有按钮组件与语义 token，不创建新视觉系统。
- 控件可通过键盘操作，加载中设置禁用/忙碌状态，失败保留现有安全错误呈现。
- 三档布局和八张 QA 视觉基线不应发生可见变化，因为默认测试数据不超过一页；如出现变化必须停止并审查，而不是更新快照掩盖差异。

## 验证设计

后端测试覆盖：

- 超过一页的消息初始返回最新记录；
- 相同时间戳的旧页游标无重复、无遗漏；
- 活动任务返回、无活动任务返回 `null`、跨用户/栅栏安全；
- 既有最早优先内部分页不变。

前端测试覆盖：

- 对话和消息游标被正确编码并传递；
- 多页消息展开后全局正序且无重复；
- 最新页 pending 状态继续触发轮询；
- 刷新发现活动摘要并恢复进度/取消；
- 活动摘要期间提问和生成摘要不可用，终态后恢复。

真实服务器 Playwright 覆盖：启动一个可控但仅测试进程可见的摘要任务，在任务活跃时刷新页面，确认进度/取消入口从服务端恢复；不得拦截路由或使用浏览器存储。

最终重新运行完整 Python、Vitest、类型检查、Lint、构建、Playwright、设计契约、依赖审计及差异检查。QA 验收不得新增跳过项。

## 兼容性与后续演进

- 不修改数据库结构、任务状态或已有资源 ID。
- 不修改内部上下文/报告使用的历史分页。
- 新活动任务端点和最近页语义是加法式产品 API；旧任务 ID 查询继续有效。
- 后续 SSE/WebSocket 只替换活动资源的通知方式，活动任务发现仍作为首次加载与断线重连的基线读取。
- 分布式升级时，仓库接口可替换为共享数据库/队列实现，React 不需要改用另一套领域模型。
